# Равный бюджет настройки моделей

Принято по просьбе пользователя: общий v3 — исходная точка, а не окончательный
вердикт о модели. Настраиваем отдельные промпты GPT-4.1, Luna 5.6, Luna 6.
Production prompt/model пока не меняются.

До новых вызовов фиксируем бюджет: две итерации кандидатов на одну модель,
6 общих development-входов на итерацию, один ответ на вход (12 tuning calls
на модель, всего 36). На второй итерации можно изменить только промпт на основе
development. Если первая версия без ошибок, вторая всё равно проходит одинаковую
проверку (может сохранить текст); не расходовать её бюджет на третьего кандидата.
Выбираем между двумя по минимальному числу обязательных смысловых ошибок,
затем всех needs-work, затем полезности эквивалентов; при равенстве — первый.

Для итоговой проверки: новая общая validation-выборка из 6 исходных RU/EN
примеров, три повтора на каждую модель/промпт. На тех же входах — общий v3
и выбранный персональный кандидат (108 calls). Итого потолок 144 calls,
2200 completion tokens/call, прежние model settings, без auto-retries.
Финальные промпты и выбор фиксируем до любых validation-вызовов. Новую выборку
фиксируем до начала tuning; не меняем по полученным ответам. Небольшая выборка
остаётся диагностикой, не статистическим доказательством превосходства.

Старую validation-v1 явно переводим в наблюдённые development-материалы:
она уже разобрана, поэтому больше не независима. Новый development-v2 состоит
из трудности, лёгкости, idiom-only, другого смысла typisch, EN разговорного
глагола и контрольного животного. Критерии/рубрика v1 остаются общими для всех.

Оценка: отдельный non-blind agent review для каждого exact response, не human
и не независимый judge. Отдельно считать primary/alternatives, определения,
идиомы, base; не принимать большее число вариантов за качество. Итоговые
сравнения: внутри каждой модели (общий vs tuned) и между выбранными кандидатами;
ошибки/стабильность важнее задержки. Usage и latency фактические; цена неизвестна
до подтверждения Azure тарифов. Победитель может не определиться.

В этой настройке разные формулировки — гипотезы под наблюдаемые ответы моделей,
а не утверждения об их внутренней архитектуре. Сохраняем отклонённые версии,
решения и полные ответы. Код приложения и article pipeline не меняем.
