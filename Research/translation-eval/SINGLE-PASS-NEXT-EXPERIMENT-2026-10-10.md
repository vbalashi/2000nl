# Следующий эксперимент: единый промпт и пересмотр по сигналу

Статус: предложен после принятия single-pass продуктового направления.
Платные прогоны/внедрение очереди в этом checkpoint не выполнялись.

## Базовый путь

Один версионированный основной промпт, одна выбранная модель, один запрос на
значение/целевой язык, сохранённый результат переиспользуется разными карточками.
Детерминированные проверки проверяют JSON, полный набор fieldId, отсутствие
пустых обязательных полей, актуальность source/artifact. Языковая эвристика —
сигнал, не гарантия. Семантического judge на каждом запросе нет. Отсутствие
жалобы означает отсутствие обнаруженной проблемы, а не доказанное качество.

## Предложение эксперимента

100 полных значений с реалистичной длиной определений, patterns, примеров,
идиом/объяснений/notes, разными POS и RU/EN. Сначала заморозить выборку и
разделить 30 development / 70 held-out. Старые случаи оставить как regression,
не объявлять новыми held-out. Не считать короткие fixtures полной статьёй.

На development сравнить общий v3 и один компактный общий кандидат (30 × 2 × 3
= 180 вызовов). Исправлять наблюдавшиеся общие причины: scope negation,
соответствие POS, fidelity определения, base отдельно от contextual meaning.
Не наращивать список инструкций под конкретные слова. Выбрать/заморозить один
общий prompt до held-out. На held-out по одному ответу каждой модели (70 × 3
= 210). Общий proposed cap 390, до начала нужен зафиксированный точный протокол.
Это расходы исследования, не схема приложения. Если нужна причинная оценка
v3-v4 на held-out, заранее включить дополнительное baseline-плечо; не добавлять
его после просмотра результатов.

Выбор: частота серьёзных смысловых ошибок, полезные same-sense варианты,
естественность, полный accepted response, usage/стоимость, p50/p95 задержки.
Отдельно ошибки по полям и длинам. Сначала установить допустимую границу
качества и критерий перехода, затем выбирать дешевле среди прошедших; размер
выборки ограничивает выводы. Агентская оценка помечается как таковая; часть
спорных ответов дать независимому языковому reviewer. Не запускать critic
для каждой production-карточки ради исследования.

Отдельный малый replay на уже известных плохих переводах: жалоба с entry/lang,
source fingerprint и точной версией artifact → dedup → проверка, не исправлено ли
уже → targeted review. Допустимые исходы: оставить/исправить/не уверен. Замена
только точной проверенной версии с сохранением старой, причины, модели/промпта
и возможностью отката. Не путать ошибку исходной статьи с ошибкой перевода.
Неуверенные случаи остаются в очереди для редкого review; пользователь не ждёт
разрешения спорного случая на каждом новом переводе. Жалоба не доказательство
и не повод автоматически перезаписывать все переводы.

## Цена: публичные ориентиры на 10 октября 2026

Это расчёт по опубликованным тарифам, не подтверждённый Azure invoice для
конкретных deployment. Исторические исследования с monetaryCost=null не
переписываются задним числом. Без налогов, retry, TTS и judge, без скидок input
cache/Batch. Output у reasoning-моделей включает reasoning tokens.

- GPT-4.1: $2 input / $8 output на 1M. [OpenAI model page](https://developers.openai.com/api/docs/models/gpt-4.1).
- GPT-5.6 Luna: $0.20 / $1.20 на 1M, Standard Global short context.
  [Microsoft Foundry](https://azure.microsoft.com/en-us/blog/gpt-5-6-now-available-in-microsoft-foundry/).
- GPT-6 Luna: $0.10 / $0.50 на 1M, Standard short context.
  [OpenAI pricing](https://developers.openai.com/api/docs/pricing).
  Azure deployment-specific rate ещё не подтверждён.

Формула USD = (input tokens × input price + output tokens × output price) / 1M.
В исходном A/B (initial-ab/alternatives-ab-v2.jsonl, profile v1, 12 случаев)
рабочий GPT-4.1 prompt: среднее 444.9 input / 115.4 output, ~$0.001813 за
один или ~$0.1813 за 100 подобных коротких значений. Это не production billing
и не репрезентативные полные статьи.

На общем research v3, 18 held-out ответов: GPT-4.1 740.3/117 токенов → $0.2417
за100; Luna5.6 739.3/219 → $0.0411; Luna6 739.3/200.8 → $0.0174. Разные модели
генерируют разный объём. Это фактический usage небольших fixtures, цена оценочная.

Иллюстрация полного значения: **предположение** 2000 input + 1000 billed output
(включая reasoning), не измеренное среднее. На100 = 200k input + 100k output:
GPT-4.1 $1.20, Luna5.6 $0.16, Luna6 $0.07. Наодно: $0.012 / $0.0016 / $0.0007.
Для реальной полной карточки нужны p50/p95 usage на репрезентативной выборке.
Переиспользование сохранённого перевода не требует нового provider-вызова.

При 1% жалоб и двух дополнительных вызовах того же размера на пересмотр расход
вызовов увеличивается примерно на2%, а не вдвое. Другая модель/длина critic
изменит денежный коэффициент; это иллюстрация, не оценённая доля жалоб.
