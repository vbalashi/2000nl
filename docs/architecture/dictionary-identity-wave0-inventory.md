# Dictionary Identity Wave 0 Inventory

Date: 2026-07-24
Status: static repository inventory; production audit still required

This report inventories identity-sensitive surfaces before any binding-ledger,
uniqueness, re-import, or lookup-completeness change. It is not authorization
to mutate schema or production data.

### Reproduced corpus evidence

A read-only scan of the sorted `db/data/words_content/*.json` snapshot on
2026-07-24 produced:

| Measure | Count |
| --- | ---: |
| JSON artifacts parsed | 17,959 |
| Distinct current `(headword, meaning_id)` keys | 17,389 |
| Current-key groups spanning multiple payload POS values | 539 |
| Minimum variants overwritten by one-row-per-current-key behavior | 570 |

`goed` meaning 1 demonstrates why filename and payload evidence must remain
separate: the snapshot contains `goed_bn_1.json`, `goed_bw_1.json`, and
`goed_zn_1.json`, while their payload POS values are respectively null, `bw`,
and `zn`. A binding resolver must not silently convert the filename's `bn`
token into proven provider POS.

The scan derives `meaning_id` exactly as the current parser does: integer
payload value, then numeric filename suffix, then `1`. A reproducible manifest
tool must persist this result and its checksum; this ad hoc verification is not
the approved manifest.

## Lookup truncation and count risk

Strict authenticated lookup currently passes `p_limit: 10` from
`apps/ui/lib/platform/platformApi.ts:279-305`; public catalog lookup does the
same at `platformApi.ts:513-535`.

The active indexed resolvers:

- default/clamp the requested limit to 10/50 and apply `LIMIT v_limit`
  (`db/migrations/099_indexed_authenticated_lookup.sql:4-32,280-286`;
  `db/migrations/093_indexed_public_catalog_lookup.sql:5-32,165-170`);
- hydrate only that limited `resolved` CTE;
- calculate `meanings_count` with a window over the limited set and partition
  only by dictionary/language/headword, not POS/source group
  (`099...sql:329-365`; `093...sql:248-284`);
- calculate response `total` from the same limited payload set
  (`099...sql:407-428`; `093...sql:325-346`).

Therefore current `total` is returned-count, not full candidate-count, and
`meanings_count` can be both truncated and grouped at the wrong semantic
scope. Restoring POS/sense variants can make this visible even if today's
common headwords fit under ten.

Required completeness fixture:

- one clicked form/headword with more than ten eligible entries;
- multiple POS groups and at least one same-POS homograph group;
- exact approved manifest entry-ID set;
- authenticated and public-catalog variants where entitlement permits;
- assertion that paginated/complete response ID union equals the manifest set;
- separate assertions for `returnedCount`, `totalCount`, `isComplete`, and
  source-group `senseCount`.

## Reproducible audit checklist

Run against a disposable production-like snapshot first. Read-only production
queries require normal operational approval and must not print secrets.

### 1. Pin repository and source snapshot

- [ ] Record `git rev-parse HEAD` and dirty status.
- [ ] Record dictionary source root, file count, deterministic sorted manifest,
      manifest revision, and SHA-256 checksum.
- [ ] Record importer/parser versions and fingerprint canonicalization version.
- [ ] Preserve raw POS evidence, filename, payload meaning/POS, metadata index,
      and content fingerprint per artifact.

### 2. Re-scan writers and conflict targets

```sh
rg -n --glob '!db/migrations/archive/**' \
  'insert into (public\\.)?word_entries|INSERT INTO (public\\.)?word_entries|UPDATE (public\\.)?word_entries|DELETE FROM (public\\.)?word_entries|ON CONFLICT \\(dictionary_id, language_code, headword, meaning_id\\)' \
  db packages apps/ui
```

- [ ] Classify every hit as source-managed, user-owned, fixture/test, or
      historical replay.
- [ ] Locate non-SQL clients that call create/copy/update/delete RPCs.
- [ ] Confirm each live writer has one fail-closed disjoint identity target.

### 3. Discover authoritative FK consumers

```sql
SELECT
  conrelid::regclass AS consumer_table,
  conname,
  pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE contype = 'f'
  AND confrelid = 'public.word_entries'::regclass
ORDER BY 1::text, conname;
```

- [ ] Diff this result against the table above.
- [ ] Record row counts, distinct referenced UUID count, orphan count, and a
      deterministic checksum per consumer.
- [ ] Enumerate dependent views/functions with `pg_depend` and
      `pg_get_functiondef`, especially delete/update paths.

### 4. Inventory soft UUID references

```sql
SELECT count(*) AS copied_entries,
       count(*) FILTER (
         WHERE NULLIF(raw->>'sourceEntryId', '') IS NOT NULL
       ) AS with_source_entry_id
FROM word_entries;
```

- [ ] Validate every UUID-shaped `sourceEntryId`; count missing targets,
      self-links, cross-user/cross-dictionary anomalies, and duplicates.
- [ ] Search JSON columns, export formats, logs/analytics schemas, and client
      fixtures for entry IDs.
- [ ] Enumerate observed Platform V1 consumers and their last-seen usage.

### 5. Reproduce identity collision evidence

- [ ] Group manifest artifacts by current
      `(dictionary, language, headword, meaning_id)` and list multi-POS groups.
- [ ] Group by proposed source key and prove uniqueness within scheme version.
- [ ] For every current UUID, compare the versioned stored-content fingerprint
      to source artifacts and classify exactly one/no/multiple match.
- [ ] Emit explicit `ambiguous` and `rejected` records; do not resolve them by
      input order.
- [ ] Run the same manifest twice and assert zero identity diff.

### 6. Capture preflight UUID invariants

- [ ] Export sorted pre-existing UUID set.
- [ ] Capture each consumer's row count/checksum by existing UUID.
- [ ] Capture source/user dictionary counts, user state on source entries, and
      retired-candidate state.
- [ ] Prove the restorable snapshot and write/import pause.

### 7. Reproduce lookup completeness

- [ ] Run current strict lookup with the greater-than-ten fixture and record
      `items.length`, `total`, `meanings_count`, and sorted IDs.
- [ ] Show the current truncation explicitly.
- [ ] Test the future complete/paginated contract against the approved manifest
      union for authenticated and catalog paths.
- [ ] Verify counts are independent of page size and grouped by approved
      `source_group_key`, not limited response rows.

### 8. Postflight and rollback rehearsal

- [ ] Assert `pre UUIDs` are a subset of `post UUIDs`.
- [ ] Assert new UUIDs equal only approved restored artifacts.
- [ ] Assert existing-UUID consumer counts/checksums are unchanged.
- [ ] Assert restored UUIDs have no historical user state.
- [ ] Rebuild and verify word forms/search documents.
- [ ] Rehearse pre-exposure restore and post-exposure retire/disable
      roll-forward.
