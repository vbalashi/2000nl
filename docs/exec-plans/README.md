# Execution plans

Plans for implementing an agreed piece of work; not an article calendar or an
archive of experiments. Start from the owning issue and its specific plan.

- `active/`: work in progress, contracts, handoffs and validation/rollout steps.
- `completed/`: historical completed plans; verify current behavior separately.
- Existing files at this level: retain stable links; inspect their own status.

Each new plan should name the owning issue, scope/layer, current state,
implementation steps, validation, rollout/rollback when relevant, and links to
intent and evidence. A file in `active/` does not prove the work is still active:
check the issue and worktree before resuming.

For investigation use [research](../research/README.md) or [discovery](../discovery/README.md).
For websites/media use [marketing](../marketing/README.md).
For implementation boundaries use [../../AGENTS.md](../../AGENTS.md).
