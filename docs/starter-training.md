# Starter training for new learners

After the saved-training page opens, a new learner receives a main meaning training named “Dilum 100”, based on a configured curated collection. The recipe references existing dictionary entries; it does not copy dictionary content or select frequency ranks. The collection can contain more than 100 entries because each headword can have several meanings. It uses both meaning directions and ten cards per session. Interface and translation language preferences remain independent.

An installation operator provisions the curated collection and its word-entry memberships separately from the public application. The dictionary content and editorial selection are external resources; no private content or dictionary identifiers are shipped here. Configure `private.starter_training_config.dictionary_id` to a generally published, free, curated Dutch dictionary, and `collection_id` to its Dutch curated collection. All collection entries must be active entries of that dictionary. Verify membership, accessibility for free accounts, eligible cards, and the actual dictionary version before configuring. The starter remains pending if the collection is missing, empty or has entries outside that dictionary. The normal curated collection catalog provides access to the collection for existing users too; creating a starter does not modify their saved trainings or learning progress.

New accounts are marked pending at registration; missing configuration does not prevent registration. The setup page reads the recipe and initialization status atomically. Pending initialization is retried independently when opened or refocused, and once per minute while visible. Operators can inspect aggregate statuses and `last_failure` in `private.starter_training_initializations`; relevant failures include `primary_dictionary_unavailable`, `starter_collection_unavailable` and `starter_cards_unavailable`. A marker is created only for new accounts, not inferred from an empty setup. Successful initialization is terminal, so deletion does not restore the starter. If a user saves anything before recovery, their changes take precedence and initialization becomes superseded.

Migration 364 is a fresh-install application baseline. Managed installations require a separately reviewed retaining forward migration, provisioned editorial collection, access verification and release validation. Applying this baseline or changing traffic is not authorized by this document.
