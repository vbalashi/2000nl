# Starter training for new learners

After the first saved-training page opens, a new learner receives one saved main meaning training, “Dilum Nederlands — Top 100”, scoped to the configured primary Dutch dictionary, spoken ranks 1–100, both directions and ten cards per session. The existing scheduler introduces new meanings in the word-to-definition direction first. Interface and translation language preferences remain independent; the existing onboarding teaches creation and saving of another training.

This feature owns the starter recipe, not the primary dictionary and material-preference policy (issue #8). An installation operator must explicitly configure the primary dictionary after importing and publishing its data and spoken frequency ranks. Configuration is local to the installation; no dictionary identifier or private content is shipped here. As a database owner, set `private.starter_training_config.dictionary_id` to the chosen generally published, free, curated Dutch dictionary UUID. Before doing so, verify that spoken ranks 1–100 all exist and that each has a matching active headword in the dictionary. Do not point it at a personal or restricted dictionary.

New accounts are marked pending at registration; missing configuration does not prevent registration. The setup page reads the recipe and explicit initialization status atomically. While a new account is pending, the temporary fallback cannot start, but creating a separate training remains available. Pending initialization is retried independently of the setup read when opened or refocused, and once per minute while visible, and an operator can inspect aggregate statuses and `last_failure` in `private.starter_training_initializations`. Configuration failures include `primary_dictionary_unavailable`, `spoken_frequency_unavailable` and `dictionary_frequency_unavailable` and `starter_cards_unavailable`. The marker is created only for new accounts, not inferred from an empty setup. A successful initialization is terminal, so deletion does not restore the starter. If a user saves anything before recovery, their changes take precedence and initialization becomes superseded. Existing accounts are not modified.

Migration 302 is a fresh-install application baseline. Managed installations require a separately reviewed retaining forward migration, dictionary/frequency provisioning and release validation; applying this baseline or changing traffic is not authorized by this document. Retrying occurs when the learner next reads saved training after configuration is repaired.
