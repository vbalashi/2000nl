Owning #742/#747, draft PR#748. Видео владельца: [NOS Journaal in Makkelijke Taal](https://www.youtube.com/watch?v=8_WR5b2FJfY), 16 октября, дороги/мосты, Литва, нападения на парикмахерские.

не подтверждение масштабирования на часовые видео.

## Разрешение и фактический результат

В последующем поручении владелец разрешил выполнить pilot, использовать author-provided
captions AudioFilms и добавить результат в свой аккаунт. Затем явно уточнил создать
отдельную новую коллекцию с подходящим названием. Этим заменён прежний discovery-only
запрет на данную конкретную membership mutation; schemas/deployment/shared publication
и обучение пользователя это не разрешает.

Создана **YouTube — NOS: wegen, bruggen en Litouwen (16-10-2026)**: **246 уникальных
entry IDs**, включая две sole-idiom записи. Число подтверждено отдельным DB read и
в существующей Chrome Nikolai Library владельца. Account match проверен по точному
email и в UI; UUID/email/полный dictionary content не публикуются.

Create/list membership выполнены через существующие `create_user_word_list` и
`add_entry_to_user_list` с server-verified owner, authenticated role и RPC access
checks, из административной operator session — это не новый model SQL tool и не
обход через QA login. Сначала dry-run всей транзакции с rollback, затем commit.
Сверены hash всех доступных user_card_status rows и число user_card_action_events
до/после внутри транзакции: без изменений. Ни enrollment, ни review, ни Known не
выполнялись; training session не запускалась. Проверено лишь содержимое/отображение,
не число eligible exercises во всех режимах.

**Known не исключались из состава.** Синтетический test dictionary не использовался;
lookup включал owner-readable private scope, выбранные target IDs принадлежат
существующему VanDale. Копии словарных статей и новые generated private entries
не создавались.

## Что выполнено и сколько заняло

| Этап | Наблюдение |
| --- | --- |
| Capture | AudioFilms YtDlpProvider с `language=nl, sourceKind=manual`; 141 cue; ~1,69s |
| NLP | spaCy3.8.11 + nl_core_news_sm3.8.0, CPU; 1245 tokens, 1100 alphabetic occurrences |
| Preparation | ~0,72s: load~0,55s, parse~0,17s; peak RSS~175MB всего Python процесса |
| Candidates | 298 lemma/POS proposals; 83 syntactic construction occurrences, не 83 подтверждённых идиомы |
| Lookup baseline | 470 unique form/lemma/expression queries; 30 последовательных chunks≤16; суммарно~30,99s |
| Targeted recovery | 29 дополнительных запросов, 2chunks; ~3,08s |
| Sense review | In-session agent читает contexts/существующие определения; отдельные tokens/стоимость/время не измерены |
| Result | 246 unique memberships после dedup и добавления выбранных expression targets |

[Санитизированные metrics](result-20261018.json). Lookup — existing RPC per query
в одном read-only SQL запросе на chunk: это сокращение round trips, **не** set-based
batch dictionary engine и **не** замер production HTTP/audio/projection latency.
Все обращения последовательные с statement deadlines, не load test. Часть recovery
запросов повторяет baseline: следующему coordinator нужен общий cache.
Cache cold/warm и конкурентная нагрузка не сравнивались. Числа не складывать с ручным
review в обещание времени end-to-end для пользователя.

Paid subtitle fallback/ASR/standalone LLM API **не использовались**. Поэтому платных
внешних вызовов нет, но общая цена агентной работы **не измерена**, не равна нулю.
Первый source fetch делал metadata read и provider повторно запрашивал metadata;
это ещё одна будущая возможность переиспользовать retrieval receipt, не новая API
реализация. AudioFilms код не менялся, app integration/deploy не делались.

## Найденные ошибки и исправления

- Parser неверно предлагает `brugg`, `uitbreeken`, `smeeren`, `aanvlen` и т.п.
  Исходные формы и dictionary trusted forms позволяют восстановить большую часть.
  В synthetic check `vertrouw` тоже не лемматизирован в `vertrouwen`: есть кандидат
  связи с `op`, но нет гарантии правильной lemma.
- Частицы дали двойной prefix `aanaanpakken`. Правило исправлено. Другие сомнительные
  `zienlaten`, `inhouden` не приняты лишь из-за существования похожей строки.
- Sentence parser дробил заголовок на capitals без terminal punctuation. Добавлено
  объединение таких proposed spans; стало118 предложений вместо122. Это эвристика,
  ещё не оценённая на независимых субтитрах; ellipsis original остаётся в source cues.
- `Denk` exact lookup возвращал партию DENK; исправлен выбор `denken` по контексту.
- `stalen` приводило к `stelen`, хотя в видео материал моста. Этот ложный target
  исключён; `staal` не добавлен скрыто вместо adjective.
- `tank` выбран sense2 (военная машина), `aanpakken` sense2, `uitbreken` sense2,
  `band` relation sense, `smeren` sense2, `raken` state-change sense4. Forest/bunch
  для фамилии Bos и literal `keutel` не добавлены.
- `gaan over`, `gaan om`, `uitleggen`, `doorgaan`, `nadenken`, `uitvoeren`, `horen bij`
  используют существующие самостоятельные IDs с выбранными смыслами.
- Для `in de gaten houden` и `in het holst van de nacht` нет самостоятельного
  headword lookup hit, но найдены **sole matching idioms** в отдельных exact entries
  без ordinary definition. Добавлены именно эти две узкие записи (`gat` sense5 и
  `holst` idiom), не literal hole/другие выражения. Presentation content bindings
  находятся в lookup receipts. Их следует тренировать в idiom mode; общий механизм
  выбора одного из нескольких idioms по collection membership этим не решён.

## Остатки и ограничения качества

Сохранены17 candidate questions после сверки expression targets. Среди отсутствующих
по выполненному lookup: `verkeersminister`, `vervanging`, `scheepsbouwer`,
`vooruitschuiven`, `vluchtelingenkamp`, `kapperszaak`, `vernieling`, `reparatie`,
`scootmobieletje`; часть других — geographic/proper names. Ещё `bekend worden` и
`een paar` не подменены неподходящими смыслами. Это **missing in this scoped lookup**,
не доказательство отсутствия во всех corpus/provider/research dictionaries.

Parser exclusions также содержат вопросы отдельно: cybersecurity `inbreken`,
material `stalen`, `verdwaalde kogel` и некоторые constructions не надо объявлять
шумом навсегда. Они не автоматически сгенерированы и не добавлены как заведомо
неверные existing meanings. One-shot personal draft queue — следующий этап review.

Не проводилась слепая/независимая лингвистическая оценка всего результата. Human owner
может просмотреть live collection; agent selection не заявляется гарантированно
правильным для каждого occurrence. Нет held-out precision/recall или полного
обнаружения всех выражений. Одна lemma/POS record всё ещё может требовать нескольких
смыслов; несколько отдельных случаев (например ander/anders, denken) вручную
разведены, общий automatic occurrence clustering не реализован.
