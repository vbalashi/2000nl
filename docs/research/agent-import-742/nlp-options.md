# Dutch NLP: варианты для внешнего пилота #742

Дата проверки первичных источников: 2026-10-18. Статус: предложенный эксперимент,
не выбранная production-зависимость. Установки, скачивание моделей и обработка
видео в рамках этой записки не выполнялись. Скорость, память и качество ещё не измерены.

## Рекомендация

Начать с локального CPU baseline: spaCy `nl_core_news_sm` для токенов, лемм и
синтаксиса плюс свои прозрачные правила и словарь известных выражений. Сравнить
со Stanza на одной размеченной выборке, а Alpino оставить независимым Dutch-specific
контрольным вариантом для трудных конструкций. Не выбирать библиотеку по общему
benchmark: субтитры с обрывками и ошибками отличаются от письменного текста.

Важное различие: правило сопоставления детерминировано **при заданном разборе**.
Сам разбор и лемматизация обученной моделью — предсказания и могут ошибаться.
Библиотека не гарантирует правильный предлог, восстановление отделяемого глагола,
обнаружение идиомы или выбор словарного значения. Повторяемость запуска не означает
лингвистическую правильность. Это инженерный вывод из устройства предлагаемых
компонентов; гарантии качества на выбранном видео источники не дают.

## Проверенные возможности

| Вариант | Что подтверждено документацией | Роль в пилоте |
| --- | --- | --- |
| spaCy Dutch | `nl_core_news_sm` содержит морфологию, parser и lemmatizer; официальный список указывает модель 3.8.0, пакет около 12 MB, жанр news/media | Небольшой первый baseline; размер пакета не равен рабочей памяти |
| spaCy DependencyMatcher | Находит узоры в дереве зависимостей; требует уже заполненные `dep` и `head` | Правила для кандидатов конструкций, включая несмежные токены |
| Stanza | Dutch pipeline документирован; доступны tokenize/POS/lemma/dependencies, настройка CPU/GPU и выбор пакетов | Альтернатива на тех же предложениях, без LLM |
| Alpino | Dutch parser, вывод dependency triples, включая `pc` и `svp` | Проверка связок с предлогом и отделяемых частиц; не смешивать его метки с UD |

Источники: [spaCy Dutch model card](https://spacy.io/models/nl),
[DependencyMatcher API](https://spacy.io/api/dependencymatcher),
[Stanza getting started](https://stanfordnlp.github.io/stanza/getting_started.html),
[Stanza processors](https://stanfordnlp.github.io/stanza/pipeline.html),
[Alpino guide](https://www.let.rug.nl/vannoord/alp/Alpino/AlpinoUserGuide.html).

### Как искать выражения

Первый путь — словарь уже известных выражений: варианты лемм, допустимые формы и
синтаксические ограничения. Второй — синтаксические кандидаты: глагол с частицей,
глагол и предложная группа, рефлексивная конструкция. Третий — агентская проверка
непокрытых фрагментов. Существование синтаксической связи ещё не доказывает,
что сочетание — самостоятельная идиома или что у него есть подходящая статья.

Для `ik bel hem op` нужно восстановить кандидата `opbellen` и сохранить раздельные
исходные позиции. Для `vertrouwen op` предлог может находиться не рядом с глаголом.
Для свободного обстоятельства нельзя автоматически образовывать словарную связку.
Alpino явно различает `svp` (отделяемая частица), `pc` (предложное дополнение),
`mod` (модификатор); это полезные сигналы, а не обещание безошибочного разбора.
[Alpino dependency definitions](https://www.let.rug.nl/~vannoord/alp/Alpino/adt.html).

Нельзя заранее удалить стоп-слова из исходного предложения. Фильтровать одиночные
служебные кандидаты следует после извлечения выражений. Статус Known не удаляет
запись из состава коллекции: это личное состояние обучения, а коллекцию можно
передать другому человеку. Не дедуплицировать все употребления по одной лемме до
resolution: одинаковая лемма может иметь разные значения.

## Минимальный сопоставимый эксперимент

1. Зафиксировать исходные субтитры, хеш и временные отметки. Выделить вручную
   проверенную выборку примерно 100 предложений: обычная речь, короткие реплики,
   ошибки субтитров, отделяемые глаголы, предлоги, выражения, переключение языка.
   Добавить небольшой отдельный набор искусственных контрольных пар; его оценки
   не смешивать с оценками настоящего видео.
2. Зафиксировать одинаковую сегментацию для сравнения parser; отдельно оценить
   собственную сегментацию каждого pipeline. Граница subtitle cue не равна границе
   предложения. Сохранить связь объединённого предложения со всеми cue IDs.
3. Прогнать spaCy small и Stanza CPU на одинаковом вводе. Alpino проверить на
   подмножестве трудных случаев; полный прогон добавлять только при полезном выигрыше.
4. Экспортировать одинаковые JSONL-поля: source spans, surface, proposed lemma,
   POS, relation evidence, expression candidate, context spans, extractor version.
   Не перезаписывать исходную форму нормализованной строкой. Смысл ещё не выбран.
5. Посчитать точность лемм, precision/recall выражений отдельно по типам, ошибочные
   объединения и разрывы. При маленькой выборке публиковать числители/знаменатели,
   не только проценты. Разногласие парсеров — кандидат на проверку, не уверенность.
6. Только после этого измерять, сколько записей действительно требует LLM.
   Нормализация смешанного школьного списка — отдельная стадия с явно заданным
   целевым языком и сохранёнными переводом/определением; это не задача Dutch parser.

Это план, а не проведённый benchmark. Один видеоролик проверяет пригодность пилота,
но не доказывает качество на всех темах и источниках.

## Версии, лицензии и ресурсы

Перед воспроизводимым запуском фиксировать Python/runtime, библиотеку, точный model
package/checksum, processor list, rules hash, CPU/OS/threads, batch size и device.
Словарь выражений тоже версионировать. Stanza различает default и default_accurate;
не включать более тяжёлый пакет или transformer неявно.
[Stanza packages](https://stanfordnlp.github.io/stanza/models.html).

Лицензии учитывать раздельно для кода и моделей: spaCy code — MIT,
Dutch model card — CC BY-SA 4.0; Stanza code — Apache 2.0, но это не подменяет
проверку лицензии конкретных скачиваемых весов и treebank; Alpino сайт указывает
LGPL. Сохранять notices и точные лицензии выбранных артефактов перед распространением.
[spaCy license](https://github.com/explosion/spaCy/blob/master/LICENSE),
[Dutch model license](https://spacy.io/models/nl),
[Stanza license](https://github.com/stanfordnlp/stanza/blob/main/LICENSE),
[Alpino distribution](https://www.let.rug.nl/~vannoord/alp/Alpino/).

Замеры: download bytes отдельно; cold load wall time; warm tokens/second;
peak RSS; CPU seconds; размер JSONL; p50/p95 времени чанка; ошибки и timeout;
3 повтора на одинаковом CPU. Установить явный предел длины предложения/чанка,
логировать превышения, не терять их молча. Сначала CPU без GPU и платных API.
Ресурсный бюджет будущего worker рассчитывать по измеренному RSS и throughput,
а не по размеру wheel или длительности видео. Никаких чисел времени/стоимости до
первого реального прогона не обещать.
