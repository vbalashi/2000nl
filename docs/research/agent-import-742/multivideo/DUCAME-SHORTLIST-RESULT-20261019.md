# Автоматический DUCAME shortlist: выполненное сравнение

2026-10-19, #742 / draft PR #748. Продолжение [первого пилота](LEXICON-PROBE-RESULT-20261019.md). Внешние скрипты; приложение, БД и пользовательские коллекции не менялись.

## Что добавлено

Теперь выражение не выбирается вручную. Скрипт читает опубликованный JSON lemma-index как данные (не импортирует `indexes`), выбирает записи по леммам исходного предложения, учитывает `|`-альтернативы и число повторений лемм. Полный вариант отбора использует три отдельных представления: исходные леммы, нормализованные местоименные наречия, основы именных сложных слов. Затем только выбранные канонические формы разбираются Alpino и превращаются в строгие структурные запросы. Из совпадений извлекаются конкретные компоненты, а не всё предложение.

Отбор не получает эталонные выражения. Эталон используется только после завершения поиска, для оценки. Сохраняются перекрывающиеся кандидаты; equivalent source-token sets объединяются, поэтому это адаптер библиотеки, не полная upstream annotation с её правилами удаления вложенных результатов. Подробности и ограничения [проверены по исходникам](DUCAME-SHORTLIST-NOTES-20261019.md).

## Результаты на прежних 32 предложениях

| Вариант | Канонических кандидатов | Строгих находок | Точные ядра / 23 | Частичное пересечение / 23 |
|---|---:|---:|---:|---:|
| Исходные леммы | 82 | 9 | 3 | 8 |
| Три представления лемм | 82 | 9 | 3 | 8 |
| Три представления + разделение пунктуации перед парсером | 83 | 8 | 3 | 7 |

«Частичное» означает IoU≥0.5 исходных токенов, не семантическую правильность и не официальную PARSEME-метрику. В первом варианте exact precision .333, recall .130, F1 .188; relaxed precision .889, recall .348, F1 .500. Невалидных привязок и исключений: 0. Три представления здесь ничего не добавили; это не доказательство их бесполезности на других материалах.

Примеры найденных конструкций:

- `gebruik ... maken van` — точное ядро совпало, хотя каноническая форма библиотеки записана иначе.
- `af en toe`, `op eigen benen staan` — точные границы.
- `ja en amen` найдено отдельно от глагола `zeggen`; эталон включает глагол.
- `zo trots als een pauw` содержит дополнительное `zo` относительно эталона.
- `op je bek gaan` включает переменное местоимение; эталон его исключает.
- `goed in zijn vel zitten` сопоставлено с исходным `lekker in zijn vel zitten`: совпадение структуры ещё не доказывает правильность нормализованного выражения/смысла.
- Более общее `op iets staan` перекрывается с `op eigen benen staan`. Для будущих карточек нужна проверка специфичности, иначе получим лишний вариант.

Технически низкий exact score не означает шесть заведомо неверных выражений: значительная часть различий — политика границ. Но и relaxed score не даёт права автоматически принять всё. Агент Sol в прежнем эксперименте давал 21/23 exact cores; словарный matcher его по полноте здесь не заменил.

## Где теряются выражения

Потери разделяются по стадиям:

1. **Покрытие/нормализация shortlist.** Для `opkomen voor`, `meevallen`, `afhangen van` shortlist пуст. На таких глаголах текущая библиотечная лексика и нормализация не обеспечивают универсального учебного словаря. Простым поиском буквальных форм в DUCAME не найдены также `in eerste instantie`, `scheutig`, `comfortzone`, `moeite ... waard`; отсутствие строки не равнозначно полному семантическому аудиту всех вариантов.
2. **Синтаксическое сопоставление.** `iets op de rit krijgen` попадает в shortlist как DCM11803, но строгого совпадения не даёт. Дополнительная карточка не должна генерироваться только потому, что один matcher её пропустил.
3. **Политика компонентов.** Переменные местоимения, сравнительные усилители и границы короткой формулы различаются между DUCAME и учебным эталоном. Нужно сохранить исходные компоненты и отдельно согласовать учебное ядро.
4. **Смысл.** Даже строгий структурный результат может быть слишком общим или не соответствовать контексту. Это вход для ограниченного агента-проверяющего, не окончательная запись в коллекцию.

## Проверка подготовки текста

В raw parse некоторые формы содержат запятые в `word`/`lemma`, например `Ja,`. Поэтому выполнен отдельный проход: исходные токены и пунктуация разделены пробелами перед отправкой парсеру, затем результат привязан обратно к оригиналу. Гипотеза о повышении полноты не подтвердилась: exact осталось 3, relaxed снизилось с 8 до 7, пропало `behoefte hebben aan`. Поэтому **не принимаем эту подготовку как улучшение по умолчанию**.

## Время, запросы, воспроизводимость

Первый проход: 22.25 s, исходные 32 дерева уже закешированы, 81 новый HTTP-разбор канонической формы для 82 кандидатов (часть канонических форм совпадает после очистки). Повтор с тремя представлениями: 2.63 s, новых HTTP-запросов 0. Вариант с пунктуацией: 20.55 s, 32 новых исходных дерева и 2 новые канонические формы; остальной кеш скопирован из первого прохода. Итого за продолжение **115 HTTP-запросов к публичному парсеру, 0 платных LLM-вызовов**. Это не оценка полной стоимости нового видео и не обещание бесплатного промышленного сервиса.

Применён лимит 96 уникальных canonical IDs на проход, последовательные запросы с таймаутами и ограничением XML; в варианте токенизации максимум ещё 32 исходных предложения. `generatequeries` всегда получает сохранённое дерево — скрытый fallback parser не используется. За пределами этого материала ещё нужны ограничения на число альтернатив, длительность всего job и восстановление после прерывания; этот research runner не серверная очередь.

Runner: `scripts/research/agent-import-pilot/ducame_shortlist.py`, параметры `--alpha`, `--reference`, `--source-cache`, `--out`, необязательный `--retokenize`; требует подготовленного alpha из первого pilot и того же isolated venv. Четыре focused tests проверяют повторяемость/альтернативы лемм, отсутствующие IDs и привязку токенов. Полные приватные находки/деревья сохранены в ignored `tmp/agent-import-742/lexicon-study-20261019/{shortlist,tokenized}`. [Агрегаты, время и SHA256 эталона](DUCAME-SHORTLIST-RESULT-20261019.json).

## Вывод для следующего инкремента

Пока предпочтителен гибрид: агент извлекает выражения, словарно-синтаксический слой добавляет независимые свидетельства, отдельная проверка решает смысл и границы. Ни строгий matcher, ни near-miss не добавляют карточки автоматически. Следующий независимый вариант — лексически ограниченные правила по Alpino/Parseme-NL поверх уже сохранённого Stanza-разбора; после этого имеет смысл проверять пользу словарных подсказок для агента на свежей выборке.

Все оценки относятся к маленькому targeted development reference, уже использованному в разработке, а не к независимой человеческой тестовой разметке. Не разрешён вопрос прав на DUCAME/пакет; production adoption не принималась.
