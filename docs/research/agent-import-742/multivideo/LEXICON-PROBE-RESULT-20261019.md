# DUCAME / MWE-Finder: первый выполненный пилот

2026-10-19. Issue #742, draft PR #748. Исследование вне приложения; коллекции не менялись.

DUCAME — словарь нидерландских устойчивых конструкций с аннотированными каноническими формами. MWE-Finder строит по ним запросы к синтаксическим деревьям Alpino. Это поиск известных конструкций, включая разрывные варианты, а не свободное обнаружение новых идиом. См. [статью DUCAME](https://aclanthology.org/2024.lrec-main.8/), [демонстрацию MWE-Finder](https://aclanthology.org/2024.lrec-main.1050/) и [исходники](https://github.com/CentreForDigitalHumanities/mwe-query).

## Что выполнено

1. Изолированная установка stable mwe-query 0.1.0, Alpino-query 2.1.12, sastadev 0.4.4; отдельно проверенный sdist 0.2.0a2 и conllu 6.0.0. Stable API используется только для контрольного smoke; alpha — для настоящей аннотированной записи DUCAME и Alpino-native baseline.
2. Получены деревья 32 ранее замороженных предложений из трёх видео через публичный Gretel Alpino. Внешнему сервису передаются только предложения, без аккаунта и словаря пользователя. Таймауты, ограничение размера XML, отключённые XML entities, кеш и лимит 48 новых запросов за запуск.
3. Проверены native правила `getalpinomwes`: частицы, выбранные предложные дополнения, возвратные конструкции и лексические исключения.
4. Взята настоящая запись DUCAME 4.05 **DCM04075**: `iemand zal L:rekening CIA:met iets|iemand DO:houden`. Её аннотации обработаны библиотекой, каноническая форма разобрана Alpino, запросы alpha выполнены на расширенных деревьях. Полный индекс не импортировался.

## Структурный поиск: результат

| Предложение | Строгий запрос alpha | Near-miss alpha |
|---|---:|---:|
| Hij houdt rekening met de kosten. | 1 | 1 |
| Met de kosten heeft hij gisteren rekening gehouden. | 1 | 1 |
| Hij betaalt de rekening met zijn bankpas. | 0 | 1 |

То есть настоящее DUCAME-правило узнаёт «учитывать расходы» даже при перестановке и разрыве слов и не принимает буквальную оплату счёта. **Near-miss при этом срабатывает на отрицательном примере**: его нельзя автоматически считать найденной идиомой. Stable 0.1 без полной аннотации на разрывном положительном примере дал только near-miss; результат alpha лучше на этом конкретном smoke, обобщать нельзя.

## Независимый дополнительный baseline

На прежних 32 предложениях, содержащих 23 обязательных лексических ядра, Alpino-native дал 13 уникальных кандидатов: 5 точных попаданий, 8 вне эталона, 18 пропусков; exact precision 0.385, recall 0.217, F1 0.278. Все позиции удалось привязать к неизменным токенам; relaxed IoU≥0.5 — 6 попаданий. Каноническое поле native не нормализовано под формат эталона, поэтому строковое canonical recall не интерпретируем.

Для сравнения, прежние два общих правила spaCy-sm: 7 попаданий, 25 вне эталона, F1 0.255; агент Sol: 21, 10, F1 0.778. Это **разные методы**: native не использует полный словарь DUCAME. Его слабый результат не означает, что полный MWE-Finder тоже слабый. Сам эталон небольшой, целевой, уже использовался при разработке и не независимо размечен человеком; «вне эталона» не всегда ошибка.

## Ресурсы и ограничения

Платных LLM-вызовов: **0**. Использовался публичный parser endpoint; это внешняя зависимость без обещания SLA или бесплатности промышленной нагрузки. Число кешированных разборов и тёплое время лежат в JSON; холодный запуск прерывался при отладке импорта, поэтому достоверную холодную длительность не заявляем. Один предварительный probe находится отдельно от основного кеша. Тёплое время нельзя выдавать за время обработки нового видео.

В alpha обнаружены смешанные импорты; выполнена механическая локальная замена intra-package `from name` на `from .name`, список изменённых файлов сохранён рядом с распакованным исходником. Проба не исправляет upstream и не интегрирует пакет в приложение. На Linux дополнительно проверить регистр IRV_lexicon.xlsx. Stable при импорте печатает предупреждение о необязательном отсутствующем файле; успешные результаты выше проверены отдельно.

Полный автоматический поиск по 13 388 строкам DUCAME **ещё не выполнен**. В sdist есть лексический JSON-индекс, но нет соответствующего разобранного XML; импорт полного annotator может пытаться перестроить его. Есть конфликт BSD LICENSE против CC BY-NC-SA metadata; права на данные отдельно не установлены. См. [подробное исследование](LEXICON-ALTERNATIVES-RESEARCH-20261019.md).

## Следующие проверяемые варианты

- Использовать готовый lemma-index для автоматического выбора небольшого DUCAME shortlist по предложениям; ограниченно разобрать канонические формы, кешировать по версии словаря, затем измерить полный структурный matcher на тех же 32 случаях. Это устранит ручной выбор одного выражения в текущем smoke.
- Лексически ограниченные UD-правила по публичному Alpino/Parseme-NL словарю: тот же Stanza-разбор, но допустимые сочетания определяются словарём, а не только связью глагола с предлогом. Это отделит пользу лексикона от выбора парсера.
- Отдавать агенту строгие совпадения как проверяемые свидетельства, а near-miss — только как вопрос для проверки. Новые отсутствующие в словаре выражения оставить агентскому извлечению. Не повышать уверенность из-за одного синтаксического совпадения при буквальном/идиоматическом различии.

Воспроизводимый runner: `scripts/research/agent-import-pilot/lexicon_probe.py`. Параметры `--alpha <extracted mwe_query dir> --reference <frozen reference.json> --out <private run dir>`; запускать из изолированного окружения с указанными версиями.
