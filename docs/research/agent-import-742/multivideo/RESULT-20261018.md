## Resolver → generator was actually exercised

Available tool set: existing4read tools plus **personal_draft_propose**. The fifth
handler calls a distinct SDK Agent with a different prompt/output schema and no
write tools. The resolver actually requested it for all4phrases;4new generator
model requests completed. Three later calls reused saved drafts rather than paying
for regeneration. Read tools actually selected here: morphology_suggest and
 dictionary_search. context_read/entry_read remained available but were not selected.

Closed draft fields: candidateId,status,headword,definition,example,grammar,
relatedEntryRefs,reason. Runtime adds generated/unreviewed/unsaved metadata and
source revision/sentence references. Missing context returns needs_resolution;
unknown component references and wrong candidate IDs are rejected. Definitions and
examples are model proposals, not independently fact-checked/editorially approved.

component read/grant contract is still needed, without promoting component targets
to full-expression identity.

## Failure, recovery and work still required

Initial resolver batch1 completed in9.46s. Batch2 hit3turn cap after search and nested
4draft generations, retaining all receipts. One explicit retry from fresh resolver
context with saved drafts also exhausted6turns: searches were issued over multiple
turns. Both failed attempts are preserved. Raising a cap alone was not sufficient.

A single restricted no-tools SDK finalization used the exact last request/response
history plus already completed draft tool results. It returned6mechanically valid
decisions in2.99s without regenerating drafts. Three phrases remained deferred due
to incomplete alternative snapshot searches. This is **operator-orchestrated local
recovery**, not automatic production job resumption or a successful uninterrupted
end-to-end agent loop. No third full resolver retry was launched.

The runner can preserve per-item outcomes/drafts, enforce a phase HTTP/byte/time
cap and finalize from receipts. It still needs a reliable deterministic coordinator:
track tool budget separately from model turns; close the retrieval stage; explicitly
route unresolved work to generation; finalize a plan without relying on the model
to stop at exactly the right turn. Checkpoint replay is a research mechanism, not
fenced durable jobs, cancellation, lease recovery or retry-safe writes.

20focused tests pass including phrase anchors, forged links, unreviewed flags and
separate ledger labels for parallel nested agents. Negative validation does not
prove linguistic quality. Automated production integration tests were not run
because no runtime code changed.
