## Minimal staged implementation

1. **#743, persistent bounded text import:** one private run with immutable input/artifact hash, extraction version, candidate occurrence spans, selected language/dictionary scope and revision. Server resolution returns exact entry identities; example-only hits remain evidence. Review produces a concrete plan, then a confirmed idempotent commit creates/reuses one manual collection and adds only approved entries. Return progress and collection/training navigation. Existing collection may mix personal/base entries; multiple-dictionary training also exists. Two-collection union remains separate #746.
2. **#744, one reviewed personal article:** generate one unresolved approved candidate; display editable draft with source evidence and quality result; separate confirmation saves it and adds membership with durable receipts. Save must preserve FSRS and does not silently start learning. Keep dictionary article notes separate from proposed per-user annotations. Standalone phrase/generated-card contract remains #50; raw example occurrence is not a new phrase card automatically.
3. **#745 under #685, in-app conversation:** conversation forms the same server plan and calls the same allowlisted tools. Persist ordered messages/tool calls, run state, question IDs, pending confirmation plan revision/hash, answers, receipts and cancellation. Reload/reconnect must restore authoritative state; editing a plan invalidates old confirmation. Chat text itself grants no durable permission. A question/confirmation must be visible in-app and survive tab closure, not exist only in a model response.
4. **#747, AudioFilms adapter:** provide bounded YouTube artifact/transcript and timing through AudioFilms #22, then use the same import pipeline. Later web/PDF adapters produce that artifact/occurrence contract. Do not build a second subtitle backend or block this on #684 folder design.

Suggested job states: queued/running/needs_input/needs_confirmation/committing/partially_succeeded/succeeded/failed/cancelled. These are proposed names, not current schema. Persist per-candidate resolution/save/membership outcomes. Cancellation stops future calls; resume retries only unresolved steps within the original cumulative budget. A lost browser or expired worker lease cannot authorize additional writes. Scope safe undo to changes this run created; do not remove prior membership, articles or learning state.

Existing discovery ownership and shaped dependencies are recorded in `docs/research/agent-import-742/README.md:309–327`: #743–#747 are proposed/needs-design, not Ready. Reuse #685, #684, #87, #50 and capability #474; do not reopen closed corpus importer #397 as a user import system.

## Concrete decisions still needed

- Should private notes attach to an entry/meaning (existing table) or one card type? The former avoids duplicate note text across exercises; choose explicitly before a note API.
- What can a confirmed import do by default: collection membership alone, or also explicit learning enrollment? Existing APIs distinguish these; proposed default is membership only with a separate Train action.
- What bounded size/time/cost and retention policies should ship for pasted text and generated drafts? Existing research values are test proposals, not accepted service limits.
- Which partial result is shown when a subscriber reads an updating shared collection? #684 accepts live saved changes; choose the visible import status/receipt projection jointly without reintroducing deferred Publish.
