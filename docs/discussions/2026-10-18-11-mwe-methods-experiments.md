# Сравнение методов извлечения выражений

2026-10-18, продолжение #742. Владелец прямо разрешил исследовать внешние идеи,
экспериментировать с моделями, reasoning, лемматизацией, синтаксическим разбором
и дополнительной проверкой; стоимость пока не главный критерий.

Принято как внешний исследовательский инкремент, не изменение production:
заморозить небольшую operator-labelled выборку из трёх уже полученных источников
до сравнительных API calls, сравнить dependency proposals spaCy sm/md и Stanza
с sentence extraction, category-guided extraction, high reasoning, другой моделью,
контекстом соседних предложений и parser hints. Отдельно проверить межмодельный
veto и леммы/POS трудных слов. Нельзя объявлять operator reference независимым
human gold, challenge selection — случайной выборкой или accuracy всех видео.

Предпочтения reference: обязательные лексические ядра; optional units для спорных
коллокаций/шума ASR; ordinary single words уже покрываются основным кандидатом.
Разрывные units сохраняют token IDs и символьные позиции. Слова переменных
аргументов/местоимений не становятся фиксированными компонентами. Exact-core,
relaxed-span и canonical-form scores отдельно. Жаргон — register axis, не синоним
идиомы. Предсказания и исходная разметка не переписываются после просмотра ответов.

Бюджет новой сравнительной фазы: суммарно ≤64 HTTP calls, ≤1.5 MiB запросов,
≤96 KiB/request, ≤8192 output tokens/call, ≤30 минут с первого запроса,
без transport retries, trace export и server-side response storage. Deployment
allowlist проверен: gpt-6-luna / gpt-6.1-sol GlobalStandard, существующий Azure
resource. Это новый инкремент с отдельным ledger; прежние расходы не обнуляются.
Неизвестная Azure ставка отмечается неизвестной, не подменяется OpenAI тарифом.

Исследование библиотек/ресурсов поручено отдельному research agent согласно
явно применённому research skill; основная сравнительная реализация остаётся
в текущем checkout. Коллекции, пользовательские карточки и runtime не меняются.
Лицензии lexicon и Python wrapper проверять отдельно; публичная статья не даёт
автоматического разрешения на использование лексикона в продукте.
