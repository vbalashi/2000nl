# Единое правило подготовки полной обратной стороны Training

2026-10-17. Источник: владелец после диагностики #733 попросил унифицировать подготовку для всех тренировок, с условием не усложнять систему и не повредить существующее поведение.

Принято: полный ответ текущей карточки готовится на обоих включённых языках во время показа лицевой стороны. Переворот и Translate управляют видимостью. Подготовка вопроса, которая иногда нужна ещё до лицевой стороны, и буфер будущих карточек сохраняют отдельные обязанности.

Владелец слоя — Training UI. Небольшой модуль `TrainingAnswerTranslation` задаёт общее правило: primary hook активен при доступном содержимом и отсутствии паузы выполнения; secondary provider монтируется вокруг обеих сторон и заранее загружает проекцию. Основной перевод использует уже загруженную запись, дополнительные повторные lookup для него не вводятся. Способы обновления authoritative content остаются в соответствующих сессиях: ordinary/context, idiom, sentence. Общий низкоуровневый механизм запросов, дедупликации, отмены, повторов и событий не переписывается.

Границы: не объединяем вопрос и полный ответ в один блокирующий процесс, не меняем выбор карточек, оценки, прогресс, server API, Library и глубину буфера #723. Подготовка фонова; незавершённая генерация всё ещё может продолжаться после быстрого переворота. Этот шаг унифицирует активацию, не делает общим всё состояние разных упражнений.

Проверка: тесты фактических компонентов для обоих языков и ordinary modes, сохранения скрытого результата при reveal, переключения языка/Off и существующих idiom/sentence sessions. Известная жалоба на primary production latency остаётся отдельным неповторённым наблюдением.

Статус: принято; реализация в #733 / PR #734, выпуск отдельно от локальной проверки. Предыдущая диагностика: [подготовка текущей карточки](2026-10-17-08-current-card-translation-preparation.md).
