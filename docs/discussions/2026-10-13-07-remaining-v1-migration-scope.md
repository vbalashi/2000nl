# Что осталось на V1 и нужен ли полный перенос

Дата: 2026-10-13. Источник: вопрос владельца о конкретных операциях со словами/озвучкой и возможности перевести оставшиеся обращения 2000NL, AudioFilms и Pontix на новый API. Связано с #693 / PR #698. Актуальная очередь и карта работ дополнены в [#255](https://github.com/vbalashi/2000nl/issues/255), без создания дубликата.

Под озвучкой в проверенном первом клиенте имеется в виду воспроизведение headword из Training и Library: общий resolvePlatformV2Audio вызывает V1 audio/resolve с purpose=dictionary-headword. Это рабочий общий медиасервис; текущие V2 routes посвящены карточному lookup/actions и training, отдельного V2 audio endpoint нет. Не найдено свидетельств, что перенос всего медиасервиса в V2 уже был запланирован отдельной задачей.

Под операциями со словами: DictionarySearchTab загружает полную запись по ID через V1 fetch-entry; useTrainingTurnSelectionPort использует тот же путь через fetchTrainingWordByLookup. Поиск групп использует V1 search. Клиентские createUserDictionaryEntry/copyEntryToUserDictionary экспортированы, но текущих UI callers при поиске не обнаружено; прежде переноса нужна проверка на удаление. Серверные операции создания остаются отдельно доступны внешним клиентам.

Задачи уже есть: #255 — legacy caller inventory/retirement; AudioFilms #43 — остатки учебных действий generated-save/selected-span/old overlay; #399 — закрытие прежнего action wire/direct RPC compatibility window. Pontix использует V1 lookup/actions и в принятом текущем плане остаётся parked. Вопрос владельца о будущей миграции не считается автоматическим разрешением возобновить разработку Pontix или переделать все три репозитория.

Предложенное направление: завершить переход учебных клиентов на capability contract; ненужные wrappers удалить; по аудио/переводам/поиску/созданию записей сначала определить недостающий контракт или долгосрочный общий endpoint. Не дублировать исправную реализацию только ради имени /v2. Полный отказ от V1 пока не утверждён и не реализован. Аудит исходников не подтверждает точный deployed traffic каждого внешнего клиента.
