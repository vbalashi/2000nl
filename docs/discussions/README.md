# Обсуждения и текущие решения

Обсуждения сохраняем отдельными неизменяемыми записями, действующие решения —
в [реестре решений](../intent/current-decisions.md) и связанных ADR.
Это дополняет issues, планы реализации и журнал работ, не заменяя их.

## Правила ведения

- Перед возвращением к теме найти её в реестре, ADR и архиве по ключевым словам.
- После содержательного обсуждения создать `YYYY-MM-DD-NN-topic.md`:
  дата обсуждения (если неизвестна — дата записи с явной пометкой), тема,
  источник, вопрос, позиции участников, аргументы, альтернативы, согласованное
  решение, открытые вопросы и ссылки. Несколько обсуждений в день — разные файлы.
- Сохранять содержательный конспект, явно отделяя его от дословных цитат.
  Не приписывать участникам неозвученные решения и не считать предложение принятым.
- Старую запись не переписывать при новой дискуссии. Новая запись ссылается на
  предыдущую и объясняет, что пересмотрено. Исправления фактов также оформлять
  новой записью. Не сохранять секреты и личные данные; при их случайном попадании
  удалить их, сохранив безопасную отметку о редакции.
- После принятия решения обновить краткий реестр: только актуальная формулировка,
  причина и ссылки на обсуждение/ADR. История изменений остаётся в обсуждениях и Git.
- Для значимых архитектурных границ обновить соответствующий ADR или создать новый;
  не дублировать полный контракт в реестре. ADR описывает текущее решение со ссылками
  на его основания. Существующие исторические ADR не удалять массово.
- Статус принятия решения и статус реализации различать: одобрение не означает,
  что код уже изменён. Исполнение и тесты отслеживать в issue/exec-plan.
- На контрольной точке закоммитить записи вместе с соответствующими изменениями
  или отдельным документационным коммитом.
