# Очередь предложений и подготовка переводов

Дата записи и обсуждения: 2026-09-25. Участники: владелец продукта и Codex.
Источник: текущая задача Codex, обсуждение Example sentences / #333;
аннотации к ответу `msg_0bf37e3db98b21de016ab64148ab2487d2adf7807a5223b35d`
и последующее явное согласие владельца с четырьмя пунктами.
Это содержательный конспект, не дословная стенограмма.

## Вопрос и ход рассуждения

Владелец уточнил, выбирается ли первый пример и пропускается ли предложение
без перевода. Проверка показала: каждый исходный пример имеет свою идентичность;
отсутствующий перевод запрашивается через существующий API и сохраняется.

Владелец сформулировал цель: закреплять уже встреченное значение в контексте,
а не требовать перевода совершенно незнакомого слова. Слабые значения должны
получать больше внимания. При десяти значениях и тридцати примерах важно не
застрять на трёх примерах одного слова подряд. Обсуждались две модели:
самостоятельное обучение каждому предложению и единая очередь значений с
подстановкой примеров. Для второй модели непонятно, как переносить оценку
перевода на знание слова и сохранять индивидуальные трудности с предложениями.

Codex предложил сохранить индивидуальные состояния предложений, но управлять
допуском и введением новых примеров через исходные значения. Due — сигнал
необходимости повторения, но сам по себе не полная мера знания. Существующие
повторения предложений должны учитываться, иначе оценки теряют смысл.

Владелец также предложил заранее готовить следующий перевод: ожидание первой
карточки объяснимо, ожидание после каждого ответа портит тренировку. Codex
предложил ограничиться одной следующей карточкой, общим кешем и объединением
одинаковых запросов, без сдвига очереди или записи учебного действия.

## Принято владельцем

1. Допускать примеры конкретного значения, которое уже начали изучать или явно
   отметили знакомым; знакомство с соседним значением само по себе недостаточно.
2. Сначала обслуживать подошедшие повторения предложений.
3. Новые предложения вводить с приоритетом значений, которым нужнее повторение.
4. Вводить по одному новому примеру от каждого значения за проход:
   А1 → Б1 → В1 → А2 → Б2; внутри значения — порядок примеров в словаре.

Сохраняется отдельное расписание каждого предложения. Оценка предложения
не должна автоматически записываться второй оценкой обычной карточки.
Предзагрузка следующего перевода не меняет учебный прогресс; готовность перевода
не определяет педагогический приоритет. Первая карточка имеет явное состояние
подготовки, ошибки подготовки допускают повтор без расходования ответа.

## Приоритет и границы утверждения

Сначала исправить и измерить SQL-тайм-аут запуска, затем предзагрузка одного
перевода, затем уточнение допуска/чередования с тестами. Оптимизация SQL
совместима с последующим сужением допуска. Она не делает старый допуск через
соседнее значение окончательным продуктовым решением.

Не выбраны точная формула срочности исходного значения, правила связки двух его
направлений и поведение старых упражнений при потере допуска. Их нужно явно
уточнить в реализации/контракте, а не выдавать за уже согласованные детали.
Статус: решение принято, изменения очереди и предзагрузки ещё не реализованы.
