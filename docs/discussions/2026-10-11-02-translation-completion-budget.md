# Достаточный бюджет для полных переводов

2026-10-11, #655, продолжение текущего диалога.
[Предыдущий эксперимент](2026-10-11-01-fullcard-translation-volume.md).

Пользователь считает неприемлемым обрывать полный перевод ради малого расхода
и явно поручил существенно увеличить бюджет, измерить реальное потребление
на длинных карточках и оценить стоимость. Малый общий лимит2200 унаследован
из общего сравнения моделей; при high reasoning оказался недостаточным.

Принято для нового эксперимента: те же25 длинных реальных полных значений,
тот же v8/high и формат,32768 completion tokens (reasoning+visible output),
timeout180s вместо15s. Используется production translator с явным transport
parameter override только в исследовании, без изменения runtime. Сохранить
каждый запрос/ответ/диагностику, finish_reason, реальные reasoning/output/input,
latency и review. Первые результаты не заменять и не считать новые вызовы
бесплатным исправлением старого прогона. Transient retries max3; semantic
retries не включать. Production rollout пока не выполняется.

Тарифы сверены по official OpenAI model/pricing docs 2026-10-11: публичный
Standard reference input$0.10/cached$0.01/cache-write$0.125/output$0.50 per1M.
Это расчётная оценка, не подтверждённый тариф Azure invoice. Reasoning входит
в completion; cache/write не считать дважды. Озвучка и отдельный review model
не входят в эксперимент. Текущий checkout655-fullcard-volume/PR670 продолжает
владеть исследованием; исходные licensed artifacts остаются вне Git.
