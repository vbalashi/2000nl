# Импорт словаря: пустая база и обновление существующей

Дата: 2026-09-30. Источник: обсуждение пользователя и агента в Codex, задача #397.
Это содержательный конспект, не дословная стенограмма.

Пользователь попросил сохранить русское объяснение импортёра и разделить
первоначальную загрузку тестовой базы и обновление уже используемой базы.
Он справедливо отметил: у пустой базы нет исторических идентификаторов,
поэтому сопоставлять новые Content Nodes с отсутствующей историей бессмысленно.
Предыдущая реализация пакетировала вызовы, но продолжала вызывать функцию
сверки отдельно для каждой записи даже на пустой базе.

Принято: использовать временные staging-таблицы в одной транзакции. Для записей
без Content Nodes — вставлять узлы множествами и затем связывать родителей.
Для существующих записей — определить разницу в SQL, применять проверенную
сверку идентичности только к изменившимся узлам. Идентичный manifest остаётся
проверенным no-op. Проверки исходного manifest, дублей, структуры и ссылок
нужны и пустой базе; сопоставление с историей требуется только при её наличии.
Смена состава словаря и перенос значений между source keys сохраняют прежний
контракт: выявляются и требуют отдельного согласованного reconciliation plan.
Автоматическое удаление записей из работающей базы не разрешено этой задачей.

Пользователь согласился продолжить реализацию staging-подхода. Принятие
направления не означает завершённую реализацию или подтверждённое ускорение.
Результат проверяется на временной локальной базе: быстрый пустой импорт,
no-op, обновление одного слова, сравнение с прежней семантикой, ошибка и откат.

О прежних измерениях: 155,74 с и 9,12 с — результаты промежуточных версий от
2026-09-29. Позднейший прогон финальной тогда версии не завершился за несколько
минут; ссылка только на нагрузку хоста не была доказанным объяснением. Эти
цифры нельзя считать подтверждённой скоростью каждой последующей версии.

Русское объяснение и сценарии: [runbook](../runbooks/dictionary-import.ru.md).
