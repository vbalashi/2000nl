# Измерить длину агентского цикла до выбора рабочего лимита

2026-10-19. Владелец прямо предложил дать агенту20шагов, измерить фактическую длину, затем выбирать ограничения. Это заменяет экспериментальное ограничение4turns и последующую временную принудительную финализацию после2tools для новых запусков.

Новый review20 идёт отдельно от уже завершённых review4, на той же исходной first-pass extraction, без чтения исправленных review4 outputs. Natural tool_choice, без принудительного первого dictionarycall или принудительного завершения после2reads. Prompt просит словарные свидетельства для least-certain construction, но агент выбирает следующий вызов сам. Tool-invocation cap32 не ограничивает20serialmodelturns; scoped source/dictionary/identity guards остаются. История/фактические requestcounts, toolnames, повторы, usage и время сохраняются. Завершившиеся review4 и два их recovery не перезаписываются и не смешиваются с новым результатом.

Для отдельного измерительного phase установлен aggregate384request guard (не целевой расход),8192output/call,8MiB requestbytes и45min from firstrequest. Фактически выполненные вызовы учитываются вместе со старым phase; неизвестный usage прерванного запроса не объявляется нулевым. Default production limit не принят, runtime приложения не меняется, коллекции не записываются.
