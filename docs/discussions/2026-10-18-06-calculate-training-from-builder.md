# Расчёт тренировки из конфигуратора

Дата: 2026-10-18. Источник: обсуждение с владельцем, продолжение #712 / draft PR #749.

## Запрос и решение для тестовой ветки

В сводке раздела «Сессия» показывать ∞ вместо «Без ограничений»; у самого ползунка оставить полную подпись. Владелец предложил «Рассчитать тренировку» вместо запуска из редактора: вернуться на главный экран, показать доступность и объяснение нехватки карточек. Агент принимает это как направление локального preview, выпуск остаётся на проверке владельца.

Кнопка применяет текущие настройки через существующее сохранение аккаунтной тренировки, выбирает её и возвращает на главный экран. Расчёт доступности выполняется существующим read-only механизмом главного экрана, без создания сессии и загрузки первой карточки. Ошибка сохранения оставляет редактор открытым. Сохранение отдельной кнопкой остаётся доступным. Запуск занятия выполняется только на главном экране. Счётчики отражают доступность карточек, а не обещание точного состава будущей очереди.

Это заменяет прежний немедленный запуск из редактора. Не меняет отложенную реализацию непрерывной очереди #468. См. [предыдущие подписи](2026-10-18-05-session-size-preview-labels.md).

## Проверка

Локальный Supabase на 3100: проверены расчёт reviews-only с 0/0/1 и расчёт new-only с отдельным Start, без запуска карточек или оценок. 52 проверки TrainingTodaySetup и 11 ползунка прошли; из 85 TrainingScreen 79 прошли основным прогоном, 6 старых сценариев обновлены на расчёт → Start и прошли повторно (5 + 1). Typecheck и lint прошли; прежнее предупреждение зависимости handlePlayAudio не относится к изменению. Preview и draft PR сохранены, выпуска не было.
